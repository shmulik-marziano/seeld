## 1. החלטות הבעלים 2026-11-20

1. **שני מנועים לייפויי הכוח:** שורנס ראשי (השרת שלנו מפעיל אותו ללא ממשק), המנוע שלנו גיבוי והכנה למערכת מלאה משלנו.
2. **אין אימות SMS.**
3. **הנוסח של שורנס מאושר** לסוכנות; התבניות שלנו מעתיקות אותו מילה במילה מריצה מלאה אחת (עד אז `approved: false`).
4. **חתימה מרחוק בשירות עצמי תקינה.**
5. **מיזוג האשף** מאחורי מתג כבוי: מאושר. **פריסת פונקציות שורנס** ל-`seeld-site`: מאושרת.
6. **חיבור ישיר לשורנס** דרך ממשק שאנחנו בונים, בלי Make/Zapier, ברמת סנכרון מקסימלית; איסוף הנתונים מקומית; יעד: להחליף את שורנס בשנה הקרובה.
7. **מעבר בין דפים:** רק חמש הנקודות של הלוגו, גדולות, "חושבות/חיות". נבנה ומוזג (PR #24).
8. **לוגו מחודד** (2026-11-21): הנכסים הגזורים אושרו ויזואלית ומוזגו (PR #23).

## 4. פתוח לפני הדלקת מתג האשף

1. טקסטים שאין להם נוסח במפרט מסומנים בקוד `not in spec` ודורשים אישור בעלים.
2. מחוון "שלב N מתוך M" מוסתר עד שהשרת מחזיר `modules`; להחליט אם לחשוף תצורה לפני ס1.
3. סריקת `dist/assets` רצה רק עם `POA_DIST_SCAN=1`; הוספה ל-CI דורשת שינוי זהה ב-`.github/workflows/ci.yml` וב-`docs/platform/ci.proposed.yml`.
4. תצוגת מסמך בתוך העמוד דורשת `blob:` ב-`frame-src` ב-`vercel.json`; כרגע נפתח בכרטיסייה חדשה.
5. "ממשיכים" באזהרת 2 הדקות לא מאריך את הסשן; ה-hash של התצוגה נשלח עם האישור גם בלי פתיחת המסמך; השבת חתימה אחרי שגיאה דורשת `onStrokes` (שלב 3).

## 5. הצעד הבא, לפי סדר

1. **בעלים: החלת המיגרציה** `20261120200000_surense_connector.sql` דרך GitHub Actions → "Migrate production database" → Run workflow מ-`main`, עם `confirm=<project-ref>`; קודם `dry_run=true` (לוודא מיגרציה ממתינה אחת בלבד) ואז `dry_run=false`. לא דרך הדשבורד ולא דרך MCP (RUNBOOK ב.9). בלי המיגרציה הפונקציות החדשות מחזירות 503 (אין RPC ואין מתגים).
2. **פריסה (אחרי המיגרציה, מאושרת):** `surense-webhook` (`verify_jwt=false`), `surense-worker` (`verify_jwt=false`), `surense-sync` (`verify_jwt=true`) ל-`seeld-site`. להריץ `surense-health` ואת פעולת health של `surense-sync`. המתגים נשארים כבויים.
3. **Svix:** נקודת קצה עם כתובת `surense-webhook` (`https://<project-ref>.supabase.co/functions/v1/surense-webhook`); הבעלים מדביק את `SURENSE_WEBHOOK_SECRET` במסך הסודות; בדיקה עם לקוח בדיקה. E9100 על לקוח אמיתי רק באישור בעלים.
4. **החלטות בעלים** ב-`OWNER-STEPS.md` 6.18–6.22 (תזמון pg_cron לעובד התור, מארח הורדות מותר, חלונות שמירה, שמות מקורות, bucket לקובצי מסלקה והר הביטוח); ואז הדלקת המתגים לפי הסדר ב-OWNER-STEPS 1.10.
5. **ריצה מלאה בשורנס** עם פרטי הבעלים (הוא מקליד) לקבלת 3 ה-PDF החתומים ופורמטי המטען; שמירה מחוץ לריפו בלבד; העתקת הנוסח לתבניות (`approved: true`).
6. **פתוח ללא תלות בסדר:** `og-cover.png` עם הלוגו המחודד; חידוש `types.generated.ts` ל-RPC החדשים; הצעה לבעלים לצמצם הרשאות מפתח ה-API (להסיר מחיקה); תיקון סביבת "Preview smoke" (ראו §6).
